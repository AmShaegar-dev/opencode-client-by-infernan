# OpenCode Client <span style="color:#f5a623">by inFernan</span>

**OpenCode Client** — Android-клиент для [OpenCode V2](https://opencode.ai/v2)
с SSH-туннелем, управлением моделями, вложениями и OpenCode Go.

> *by inFernan* — независимый клиент. Не является официальным приложением OpenCode.

Подключается по SSH-туннелю или напрямую по URL, ставит OpenCode на сервер,
ведёт чаты, подключает API-ключи провайдеров и экспортирует/импортирует чаты.

Отдельный проект, не связан с `servpanel-android`.

> Сначала модель, потом провайдер: добавьте ключ каталога, провайдера формой
> или вставьте готовый JSON из инструкции хостинга. Дальше — чат с вложениями
> и импорт/экспорт.

## Возможности

- **Два режима подключения**
  - **SSH-туннель** — OpenCode слушает `127.0.0.1` на сервере, приложение открывает
    локальный проброс порта через JSch. API не доступен из интернета.
  - **Прямой URL** — сервер слушает `0.0.0.0`, приложение ходит по `http(s)://host:port`.
- **Установка OpenCode по SSH** — официальный установщик, `systemd`-служба (или `nohup`),
  фиксированный пароль API, проверка `GET /api/info`.
- **Чаты** — список сессий, поиск, переименование, удаление, отправка сообщений,
  остановка генерации, переключение модели, размышления и вызовы инструментов.
- **Провайдеры** — бесплатные модели работают без ключа; ключ можно привязать к любому
  провайдеру из каталога. Свои OpenAI-совместимые провайдеры добавляются в
  `~/.config/opencode/opencode.json` на сервере.
- **Вход через браузер (OAuth/OpenCode Go)** — как в настольной версии: выберите
  провайдера → способ «Войти через …» → приложение откроет страницу провайдера,
  дождётся подтверждения и сохранит аккаунт на сервере. Для callback на
  `127.0.0.1` порт автоматически пробрасывается по SSH.
- **Модели с переключателями** — в выборе модели видно, какие модели включены;
  переключатель пишет `providers.<id>.models.<model>.disabled` в `opencode.json`.
- **Загрузка файлов на сервер** — через SSH/SFTP в `~/opencode-uploads`, путь
  подставляется в поле ввода: файл доступен инструментам OpenCode, а не только модели.
- **Вложения в чате** — кнопка со скрепкой: скриншоты и файлы отправляются
  в модель вместе с текстом (PNG/JPEG/GIF/WebP/PDF и текстовые файлы).
- **Свои провайдеры двумя способами**, как в настольной версии:
  - формой (ID, baseURL, ключ, модели);
  - вставкой JSON из инструкции хостинга (формат V1 `provider`/`npm`/`options`
    автоматически переводится в V2 `providers`/`package`/`settings`), плюс
    полноценный редактор `opencode.json` на сервере.
- **Импорт и экспорт** — отдельный чат, все чаты сервера, полная резервная копия
  приложения (серверы и, по желанию, пароли).
- **Шифрование локальных данных** — пароли SSH и API хранятся в SharedPreferences
  в зашифрованном виде (AES/GCM, ключ в Android Keystore).

## Требования

- Android 8.0 (API 26) и выше.
- Сервер с Linux и доступом по SSH (для установки и туннеля).
- Для установки: пользователь `root` (установщик пишет `systemd`-службу в `/etc`).
- Для установки нужен интернет на сервере (`opencode.ai`, GitHub Releases).

## Обновления

Приложение проверяет последний релиз на GitHub:

- автоматически при запуске, но **не чаще одного раза в сутки**;
- вручную: **Настройки → Проверить обновление**.

Если версия новее установленной, приложение показывает описание релиза и
предлагает обновление. Можно скачать APK прямо из приложения и открыть
системный установщик. Android попросит разрешить установку из этого приложения.

- репозиторий: `https://github.com/AmShaegar-dev/opencode-client-by-infernan`;
- проверка идёт через GitHub Releases API;
- в релизе должен быть прикреплён `.apk`-файл;
- если APK не прикреплён, приложение откроет страницу релиза в браузере;
- отказ от обновления запоминается на сутки для этой версии.

Константы `GITHUB_OWNER` и `GITHUB_REPO` находятся в
`data/UpdateChecker.kt`.

## Быстрый старт

1. Откройте приложение → **«Установить OpenCode»** (или «+» → «Новый сервер»).
2. Укажите SSH-хост, порт, пользователя и пароль.
3. Нажмите **«Проверить сервер»** — приложение запомнит отпечаток SSH-ключа.
4. Проверьте порт OpenCode (по умолчанию `4096`) и пароль API (генерируется автоматически).
5. Нажмите **«Установить OpenCode»**.

Установщик выполнит:

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

затем создаст:

- `/etc/opencode/server.env` c `OPENCODE_PASSWORD=…` (права `600`);
- `/etc/systemd/system/opencode.service` с
  `opencode serve --hostname 127.0.0.1 --port 4096` (или `0.0.0.0`, если включён
  «Открыть порт наружу»);
- запустит службу и проверит `GET /api/info`.

Если `systemd` нет, OpenCode запускается через `nohup`, лог — `/var/log/opencode.log`.
Повторная установка перезаписывает службу и пароль — это безопасно.

## Подключение к уже установленному OpenCode

«+» → «Новый сервер»:

- **SSH-туннель**: хост, порт, пользователь, пароль SSH, порт OpenCode на сервере,
  пароль API. Проброс идёт на `127.0.0.1:<порт>` сервера.
- **Прямой URL**: адрес вида `https://server.example:4096` и пароль API.
  Для прямого доступа лучше использовать HTTPS-прокси: Basic Auth по HTTP
  передаёт пароль в открытом виде.

Пароль API — это `OPENCODE_PASSWORD` на сервере. Логин Basic Auth всегда `opencode`.

## Провайдеры и ключи

Экран **«Провайдеры»** (из меню чата или списка чатов):

- **Провайдеры сервера** (`GET /api/provider`): нажатие открывает выбор способа
  входа — API-ключ, OAuth-браузер или другой способ, который предлагает интеграция.
  Ключ уходит на сервер через `POST /api/integration/{id}/connect/key`.
- **Аккаунты** — сохранённые ключи и OAuth-токены видны в диалоге провайдера;
  аккаунт можно удалить (`DELETE /api/credential/{id}`), не трогая остальные.
- **Свои провайдеры** читаются из `~/.config/opencode/opencode.json` через API
  сервера, при недоступности — по SSH. Для каждой записи видны ID, baseURL,
  наличие ключа и число моделей; ключ можно заменить, провайдера — удалить.
- **«Добавить провайдера»** — обычная форма (ID, baseURL, ключ, список моделей,
  пакет). После записи выполняется `POST /api/location/reload` и проверка
  `GET {baseURL}/models` с сохранённым ключом; результат показывается в тосте.
- **«Вставить JSON вручную»** — вставляете кусок конфигурации как в инструкции
  хостинга, приложение сохраняет его и проверяет провайдера.
- **«Редактировать opencode.json»** — просмотр и правка файла на сервере
  (проверяется, что это корректный JSON; JSONC с комментариями тоже читается).

### JSON из инструкции хостинга

Поддерживаются оба формата. Старый (V1) приводится к V2 автоматически:

```jsonc
// V1 — как в панели хостинга
{
  "provider": {
    "bobiviphouse": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "BOBIVIPHOUSE",
      "options": {
        "baseURL": "https://77-91-115-251.sslip.io/api-store/v1",
        "apiKey": "sk-cvc-…"
      },
      "models": { "gpt-6.1-sol": { "name": "gpt-6.1-sol" } }
    }
  },
  "model": "bobiviphouse/gpt-6.1-sol"
}
```

После сохранения на сервере будет:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "bobiviphouse": {
      "name": "BOBIVIPHOUSE",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://77-91-115-251.sslip.io/api-store/v1",
        "apiKey": "sk-cvc-…"
      },
      "models": { "gpt-6.1-sol": { "name": "gpt-6.1-sol" } }
    }
  },
  "model": "bobiviphouse/gpt-6.1-sol"
}
```

Преобразования: `provider` → `providers`, `npm` → `package` (AI SDK-имена
получают нативный пакет или префикс `aisdk:`), `options` → `settings`,
`api` → `settings.baseURL`, `id` модели → `modelID`, `release_date` → `releaseDate`.
Если в файле нашлись V1-поля, на экране появляется подсказка с кнопкой
**«Исправить»** — она приводит весь файл к V2 и сохраняет копию остальных
настроек.

Ключ можно хранить как `{env:NAME}` — приложение прочитает переменную из
`/etc/opencode/server.env` или окружения сервера, чтобы проверить провайдера.

Бесплатные модели определяются по нулевой стоимости в `GET /api/model` и помечаются
в выборе модели как `free`.

### Вход через браузер и OpenCode Go

Диалог провайдера показывает методы из `GET /api/integration/{id}`:

1. **API-ключ** — обычный ввод. Для OpenCode Go ключ берётся в
   [консоли OpenCode](https://opencode.ai/console/go): подписка → ключ → вставить
   в приложении.
2. **Войти через …** (`type: "oauth"`) — приложение вызывает
   `POST /api/integration/{id}/connect/oauth`, открывает полученный `url`
   в браузере и опрашивает статус попытки.
   - `mode: "auto"` — провайдер сам возвращает результат на callback-адрес.
     Если `redirect_uri` указывает на `127.0.0.1`/`localhost`, приложение заранее
     поднимает SSH-проброс этого порта, чтобы браузер телефона попал на сервер.
   - `mode: "code"` — браузер показывает код; вставьте его в поле диалога,
     приложение отправит `POST …/complete` с `{code}`.
   - Ссылку можно скопировать или открыть повторно; «Отмена» удаляет попытку.
3. Другие методы (`external`, `command`, `env`) выполняются на сервере —
   приложение показывает подсказку, что именно нужно сделать.

Вход сохраняется на сервере, поэтому тот же аккаунт доступен с других устройств.
Пароли и токены в приложении не хранятся — только на сервере OpenCode.

### Включение и выключение моделей

Выбор моделей открывается на весь экран: поиск, фильтр «Все / Включённые»,
группировка по провайдеру и счётчик «Включено N из M». У каждой модели есть
переключатель; выключенная остаётся в списке серым, но её нельзя выбрать для чата.

- Переключатель правит `~/.config/opencode/opencode.json`:
  `providers.<provider>.models.<model>.disabled: true` при выключении и
  `disabled: false` при включении. Поле не удаляется: OpenCode применяет
  конфиг поверх уже загруженного каталога, и пропуск поля оставлял модель
  выключенной до перезапуска сервера.
- Основной путь — через API сервера: `POST /api/config` + `POST /api/shell`
  читают конфиг, `POST /api/experimental/fs/write` записывает его.
  **Отдельный SSH-доступ для переключения моделей не нужен** — достаточно
  работающего API (прямого URL или уже поднятого SSH-туннеля). В режиме
  «SSH-туннель» запросы идут через уже открытый туннель, отдельное подключение
  к порту 22 не создаётся, а порт OpenCode остаётся закрытым наружу. Если
  API-путь недоступен, автоматически используется прямое SSH-подключение.
- Все изменения конфига сериализуются: несколько быстро нажатых переключателей
  выполняются по очереди и не затирают друг друга.
- `/api/model` отдаёт только включённые модели. Выключенные приложение
  добавляет в список из `opencode.json`, поэтому после перезапуска их снова
  видно и можно включить обратно.
- Звёздочка у модели добавляет её в **«Избранные»**; фильтр «Избранные»
  оставляет только отмеченные модели. Избранное хранится в профиле сервера.
- Файл перезаписывается обычным JSON: комментарии JSONC при изменении модели
  не сохраняются. Для ручной правки используйте «Редактировать opencode.json».

### Уровень размышлений

Если у модели есть варианты (`variants`), в меню чата появляется
**«Уровень размышлений»**:

- «Обычный режим» — без варианта;
- «Низкий / Средний / Высокий» и другие названия из каталога модели;
- выбранный вариант отправляется в `POST /api/session/{id}/model` вместе с
  моделью и сохраняется в профиле сервера (`variantByModel`), поэтому
  применяется к новым чатам;
- текущий уровень виден в шапке чата и на кнопке модели;
- в выборе модели нажатие на модель с вариантами открывает диалог
  «Сколько думать?».

## Чаты

- **Новый чат** — создаёт сессию с выбранной моделью (`POST /api/session`).
- Отправка — `POST /api/session/{id}/prompt`, прогресс читается опросом
  `GET /api/session/{id}/message` раз в секунду до `time.completed` или ошибки.
- **Остановить** — `POST /api/session/{id}/interrupt`.
- Смена модели — `POST /api/session/{id}/model`, модель по умолчанию сохраняется в профиле.
- Пока модель отвечает, под шапкой идёт анимированная полоса, в карточке
  сообщения и внизу крутится индикатор «обрабатывает… / Модель думает…».
- Ответы показываются с блоками ```…``` моноширинно, размышления и вызовы
  инструментов раскрываются по нажатию.
- **Копировать** — кнопка у ответа модели.
- **Найти в чате** — поиск по сообщениям с переходом к найденному.
- **Повторить последний запрос** — повторная отправка последнего текста.
- **Команды** — список `/api/command`; выбор вставляет `/команда` в поле ввода.
- **Агенты** — список `/api/agent`, переключение агента для сессии.
- **Изменения файлов** — diff последнего ответа (`/api/session/{id}/diff`):
  файлы, `+/-`, патч.

### Вложения

Кнопка со скрепкой слева от поля ввода открывает системный выбор файла
(до 5 файлов, до 20 МБ каждый). Файл читается в `data:`-URL и уходит в
`files` запроса prompt — так OpenCode V2 принимает вложения без доступа к
локальному диску телефона.

- картинки (PNG, JPEG, GIF, WebP) и PDF нужны модели с поддержкой медиа;
- текстовые файлы (`.md`, `.json`, `.kt`, `.log` …) подставляются как текст;
- выбранные файлы видны над полем ввода, их можно убрать крестиком;
- в сообщении показывается имя файла и размер, а не служебная пометка.

**Почему 20 МБ?** Это ограничение OpenCode на вложение, которое передаётся
модели как `data:`-URL. Приложение не может обойти его для скрепки, но если
выбранный файл больше 20 МБ или формат не поддерживается, оно автоматически
предлагает загрузку на сервер и подставляет путь в сообщение.

**Загрузка на сервер** — меню чата (⋮) → **«Загрузить файл на сервер»**.
Файл до **200 МБ** сохраняется в `~/opencode-uploads` (имя очищается от
небезопасных символов), а в поле ввода подставляется строка
`Файл загружен на сервер: /root/opencode-uploads/…`. Дальше можно дописать
запрос — OpenCode прочитает файл инструментами. Это отличается от скрепки:
вложение живёт только в одном сообщении, а загруженный файл лежит в проекте.

Загрузка идёт потоком: сначала SFTP (файл не загружается целиком в память
телефона), затем HTTP API (`/api/experimental/fs/write`), поэтому работает и
без отдельного SSH-доступа. Если оба пути недоступны, приложение покажет обе
ошибки.

### Хранилище сервера

На экране чатов под поиском есть карточка **«Хранилище сервера»**:

- **Свободно** — сколько места осталось в домашней директории сервера (`df`);
- **Кэш файлов** — сколько занимает `~/opencode-uploads` (`du`);
- **Файлы** — список загруженных файлов с удалением по одному;
- **Очистить** — удаляет содержимое `~/opencode-uploads` после подтверждения.
  OpenCode, чаты и настройки провайдеров не затрагиваются;
- данные обновляются при открытии экрана и по кнопке обновления.

Там же показывается карточка **«Лимиты OpenCode Go»**: скользящий, недельный
и месячный расход в процентах и бюджеты (`/api/experimental/usage/limits`).
Исчерпанный лимит выделяется красным.

Запросы идут через API сервера (`/api/shell`), при недоступности — по SSH.

## Импорт и экспорт

Экран **«Данные»** доступен из списка серверов (иконка настроек), из меню чатов
и из открытого чата.

| Файл | Что внутри |
|---|---|
| `opencode-chats_*.json` | Все чаты сервера: `{app, type, version, server, sessions:[{info, messages}]}` |
| `opencode-chat_*.json` | Один чат в том же формате |
| `opencode-backup_*.json` | Серверы приложения, режимы, отпечатки, свои провайдеры |

- Экспорт использует `GET /api/experimental/session/{id}/export`, импорт —
  `POST /api/experimental/session/import`.
- Импорт принимает файл приложения, «сырой» ответ OpenCode `{data:{info,messages}}`
  и обычный `{info, messages}`.
- Резервная копия может включать пароли SSH и API — тогда они лежат в файле открытым
  текстом. По умолчанию пароли **не** включаются.
- Импорт серверов заменяет записи с совпадающим ID или названием.

### Файлы из Telegram

Мессенджеры отдают JSON как `.txt`, а системный выборщик файлов не показывает их при
фильтре JSON. Если поделиться файлом с приложением, оно сразу сохранит копию с
расширением `.json` во внутреннем кэше и покажет подсказку — такой файл выбирается
без фильтров.

## Безопасность

- Локальные секреты (пароли, SSH-ключ, passphrase, API-пароль) шифруются AES/GCM
  ключом Android Keystore (alias `opencode_mobile_secrets`); копия
  SharedPreferences на другом устройстве бесполезна.
- Поддерживается вход по **приватному SSH-ключу** (OpenSSH/PEM) с необязательным
  паролем ключа — пароль SSH при этом можно не хранить.
- SSH-ключ сервера закрепляется по SHA-256 отпечатку после проверки; при изменении
  ключа подключение блокируется.
- Для прямого HTTPS можно задать **SHA-256 пин сертификата**; при несовпадении
  соединение блокируется.
- Новые профили с внешним `http://` не сохраняются без явного разрешения
  «Разрешить HTTP без шифрования». Для localhost и частных сетей HTTP разрешён.
  Если профиль уже использует внешний HTTP, на экране чатов показывается
  предупреждение.
- В режиме SSH-туннеля в шапке отображается «защищено SSH»; API доступен только
  на loopback сервера.
- Пароль API и приватный ключ не логируются.
- Системное резервное копирование приложения отключено (`allowBackup=false`
  и правила исключения). Экспорт копии — только вручную.
- Резервные копии с паролями/ключами не шифруются приложением — храните их
  осведомлённо.

Конфигурация `~/.config/opencode/opencode.json` (или `opencode.jsonc`) читается
через `/api/shell` и пишется через `/api/experimental/fs/write`; при недоступности
этих endpoint’ов используется SSH. Загрузка файлов идёт в `~/opencode-uploads`
через SFTP, а при ошибке SSH — через тот же `fs/write`.

## Проверка

**Консольные проверки логики** (`data/Runner.kt`, 132 проверки): разбор сообщений
и сессий, стоимость и `free` у моделей, интеграции/OAuth-попытки, включение и
выключение моделей в `opencode.json` (включая `disabled: false` и поиск
выключенных моделей), конфигурация провайдеров (V1→V2, JSONC, `{env:…}`),
профили серверов, пароли. Нужен настоящий `org.json` — в `android.jar`
только заглушки:

## Ограничения

- Прогресс ответа читается опросом, а не SSE: задержка до 1 секунды, при долгих
  ответах — до 15 минут на сообщение.
- Установка рассчитана на Debian/Ubuntu-подобные системы с `apt-get` и `root`.
- Свои провайдеры, модели и загрузка файлов используют API сервера, а SSH —
  только как резервный путь. Если серверная сборка не поддерживает `/api/shell`
  или `/api/experimental/fs/write`, нужен SSH-доступ.
- Если OAuth-провайдер ждёт callback на `127.0.0.1`, автоматический возврат
  работает только при SSH-доступе (порт пробрасывается через `Ssh.LocalBridge`);
  иначе используйте режим с ручным кодом.
- JSONC-конфиг с комментариями не редактируется автоматически; переключение
  модели перезаписывает `opencode.json` обычным JSON без комментариев.
- Ключ провайдера, добавленный через каталог, хранится на сервере; в резервную копию
  приложения попадают только параметры своих провайдеров.
